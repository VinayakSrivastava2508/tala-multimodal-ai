# Executive Multimodal AI Decision Cockpit — User Guide

## Purpose

The cockpit is the presentation layer over TALA's already-computed Day 3 analytical,
creator-strategy, and governance outputs, plus the existing multimodal RAG system. It lets
an executive move: **portfolio-level finding → claim-level diagnosis → underlying evidence →
RAG investigation**, without touching notebooks or CSVs directly.

The cockpit does not recompute anything. Every number on every page is read from a
validated file in `outputs/tables/` (or, for RAG, from ChromaDB/Gemini at query time). If a
required file is missing, the page shows an error instead of a fabricated placeholder.

## Navigation

A fixed sidebar (not Streamlit's autogenerated page list) exposes six pages in this order:

1. **Executive Overview** — portfolio-level claim-status, modality coverage, fusion
   contribution, top findings, evidence gaps.
2. **Claim Diagnostic** — filterable claim table, full claim detail, mixed-theme grouping,
   one-click handoff into the RAG page.
3. **Creator Strategy** — partnership mix, content-intent mix, partnership×intent,
   official-platform comparison, competitor lessons and moat hypotheses (all descriptive).
4. **Multimodal RAG** — the original claim-investigation and open-question RAG flows,
   unchanged in behaviour, now reachable from the sidebar and pre-filled from Claim
   Diagnostic.
5. **Governance & Roadmap** — deployment-readiness gates, risk heatmap, control maturity,
   claim decision policy, ESG priorities, implementation roadmap.
6. **Methodology & Limitations** — plain-language pipeline description and the project's
   standing limitations, with CSV downloads.

Selected page, selected claim, claim filters, RAG question/filters and retrieval-trace
visibility persist in `st.session_state` while the app is running (not across restarts).

## Claim → RAG workflow

1. Open **Claim Diagnostic**, filter to the claim category/label of interest.
2. Select a claim to see its full detail (evidence counts, interpretation, caveat).
3. Click **"Investigate this claim in Multimodal RAG."** This only stores the claim ID in
   session state and switches pages — it never calls Gemini automatically.
4. On the **Multimodal RAG** page, a context panel shows the claim, category, production
   label and presentation restriction you arrived with. The claim is pre-selected in
   "Investigate a claim" mode; you must still click **Investigate** to run retrieval and
   generation.

## Data refresh process

The cockpit reads directly from `outputs/tables/*.csv`. To refresh what it shows:

1. Re-run the relevant Day 2/3 pipeline script or notebook that produces the table.
2. Re-run `python scripts\validate_synthesis_outputs.py` and/or
   `python scripts\validate_governance_outputs.py` to confirm the new file passes schema
   checks.
3. Restart the Streamlit process (or use Streamlit's "Rerun"/"Clear cache" menu) — tables are
   cached with `st.cache_data` for the life of the process and are not re-read automatically
   if a file changes underneath a running app.

The RAG page reads live from ChromaDB and Gemini at query time and does not need a restart
to pick up new evidence once the Chroma collections have been rebuilt by the existing RAG
build scripts (out of scope for this cockpit).

## Limitations

- Descriptive only: no engagement prediction, no causal claims, no "proven moat" language.
- Creator-strategy comparison is bounded to a YouTube-dominated sample (see the boundary
  notice on that page) — not a full cross-platform study.
- Automated fusion labels are NLI/rule-based, not human-adjudicated; the cockpit surfaces
  them as-is and does not reinterpret them.
- "Insufficient evidence" is displayed as a gap, never as a contradiction or falsification.
- No screenshots of the running app are checked into this repository as part of this task —
  see the delivery report for why.

## Troubleshooting

| Symptom | Likely cause | Action |
|---|---|---|
| "This page could not load a required analytical output" | A CSV in `outputs/tables/` is missing or has a changed schema | Re-run the producing pipeline/validator; do not edit the CSV by hand |
| RAG page shows "ChromaDB is unavailable" | Chroma persistent store not built or path misconfigured | Re-run the Day 3B Chroma build step |
| RAG page shows "Answer generation failed" | `GEMINI_API_KEY`/`GEMINI_MODEL` missing in `.env`, or a Gemini API error | Check `.env` locally (never through the app); the app never displays key values |
| Charts show no data | Active filters exclude every row | Loosen or clear filters; the page states "no claims match" rather than showing an empty chart silently |
